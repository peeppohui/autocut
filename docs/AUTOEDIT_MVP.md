# AutoCut: MVP автоматического монтажа

Документ описывает следующий слой проекта: не «ещё один режим», а
замкнутый цикл «выбрал папку → нажал кнопку → получил редактируемую
секвенцию в Premiere». Это продолжение уже существующего пайплайна, а не
замена ему.

## 0. Коротко

**Цель MVP.** Из CEP-панели в Premiere Pro одной кнопкой собрать черновой
монтаж: стендап, нарезка, интервью, музыка, титры-маркеры и звук с
рекордера. Результат — новая секвенция, которую монтажёр правит, а не
собирает с нуля.

**Первый жанр.** Дайджест мероприятия. Причины: материал уже разобран,
правила сняты с готового ролика, есть `digest.py`, `recmatch.py` и
`recsound.py`. Интервью — второй жанр, после стабилизации дайджеста.

**Что не делаем в MVP.**

- нативный C++-плагин Premiere;
- облако и платные API;
- финальный цвет и мастеринг звука;
- генерацию MOGRT и сложной графики;
- монтаж произвольного кино, клипа или влога «из коробки»;
- диаризацию спикеров как обязательный шаг;
- дообучение LLM.

**Главный принцип.** LLM придумывает историю, но не таймлайн. Таймлайн
строит детерминированный оптимизатор, а проверяет critic. Формула:
«LLM — режиссёр, оптимизатор — монтажёр, компилятор — ассистент
монтажа».

| рекордер | `ml/recmatch.py`, `modes/recsound.py` | слова и звук с REC-файлов |

### 1.2. Блокеры, без которых «одна кнопка» невозможна

1. **Звук рекордера в XML.** `digest.voice_audio()` режет WAV с нуля, а
   `io/premiere.py` пишет для него камерные `in/out` и длительность
   камеры. Нужно хранить в плане исходный REC-файл и его собственные
   `in/out`, а не заранее нарезанный WAV.
2. **Одна дорожка A2, а не дорожка на каждый кусок.** Сейчас имя
   дорожки — `M:<имя файла>`, поэтому каждый вырезанный WAV создаёт
   новую дорожку. В плане должен быть явный `track: "A2"`.
3. **Импорт XML.** Панель вызывает `app.project.importFiles([...])`,
   хотя проверенный путь — `app.project.importXML(File(...))`. Нужен
   тест на живой Premiere 2026.
4. **Задачи.** Отмена не работает для очереди и между шагами, не
   выставляет `finished`, теряет результаты многошаговых задач. Нет
   общего GPU-замка: два дайджеста могут одновременно загрузить
   Whisper, VLM и LLM и уронить видеопамять.
5. **Мост.** Нет токена и проверки Origin; любой локальный процесс или
   страница может запустить сборку. Для localhost-инструмента это
   обязательная гигиена.
6. **Зависимости.** `requirements.txt` не содержит `numpy`, `Pillow`,
   `torch`, `transformers`, `sentence-transformers`, `mcp`. README
   обещает `base`, а настройки по умолчанию — `large-v3`.

Эти пункты входят в M0. Пока они не закрыты, автоматический монтаж
будет демонстрацией, а не инструментом.

**Статус на 25.10.2026.**

- п. 1–2 исправлены в коде (PR-1): план хранит исходный REC-файл и его
  `in/out`, все куски идут на одну дорожку `A2`. Нужен прогон тестов и
  проверка импорта в Premiere 2026.
- п. 4 частично (PR-2): появились очередь, отмена в очереди и между
  шагами, `finished`, результаты всех шагов. Общий `RUN_LOCK` не даёт
  двум тяжёлым задачам одновременно занять видеопамять. Отдельного
  GPU-семафора пока нет — сериализуются все задачи, включая лёгкие.
- п. 5 частично (PR-2): добавлена проверка `Origin` от CSRF. Токена
  и полноценной авторизации пока нет.
- п. 3 и п. 6 остаются открытыми.

## 2. Продуктовый сценарий

1. Монтажёр открывает панель AutoCut в Premiere.
2. Выбирает папку проекта (корень, где лежат `исх/`, `звк/`, музыка).
3. Выбирает жанр, хронометраж, музыку и, при желании, «сухой» режим без
   LLM.
4. Нажимает «Собрать».
5. Панель проверяет движок; если он не запущен, запускает его сама.
6. Движок строит индекс, план, черновик, проверяет его и импортирует
   XML в открытый проект.
7. Панель показывает стадии, таймкод, предупреждения и кнопку
   «Открыть секвенцию».
8. Монтажёр правит готовую секвенцию: V1 — голос, V2 — нарезка,
   A1 — камера, A2 — рекордер, A3 — музыка.
9. Если нужно, монтажёр пишет «короче на 30 секунд» или «больше
   нарезки» — движок пересобирает план, не трогая исходную секвенцию.

## 3. Архитектура

```
Premiere Pro
  └─ CEP-панель (HTML/JS)
       └─ HTTP 127.0.0.1:8931..8933 + token
            └─ bridge.py
                 └─ jobs.py  (очередь, отмена, GPU-замок)
                      └─ modes/autoedit.py
                           ├─ ml/index.py      факты о материале
                           ├─ ml/director.py   история и биты
                           ├─ ml/editor.py     таймлайн и ограничения
                           ├─ ml/critic.py     проверка и починка
                           ├─ ml/style.py      профиль монтажёра
                           ├─ io/editplan.py   схема и валидация
                           ├─ io/premiere.py   FCP7 XML / EDL
                           └─ io/render.py     превью и финальный MP4
```

### 3.1. Слои

| Слой | Вопрос | Результат |
|---|---|---|
| Index | «Что у нас есть?» | `media_index.json` |
| Director | «О чём история?» | `edit_plan.json` с битами |
| Editor | «Какие куски и в каком порядке?» | точный таймлайн |
| Critic | «Это вообще смотрится?» | `critique.json` + правки |
| Exporter | «Как отдать в Premiere?» | XML, EDL, MP4, отчёт |

### 3.2. Границы ответственности

- Index не принимает монтажных решений. Только факты и оценки.
- Director не пишет XML и не выбирает точные кадры. Только смысл,
  биты, темы и кандидатов.
- Editor не вызывает LLM. Только ограничения, перебор и оптимизация.
- Critic не «улучшает» план сам. Он возвращает список проблем и
  допустимых правок.
- Exporter не меняет план. Он компилирует его в формат.

### 4.1. `modes/autoedit.py`

CLI:

```bash
python -m src.modes.autoedit \
  --input "E:\проект" \
  --genre digest \
  --target-sec 120 \
  --music "E:\проект\music.mp3" \
  --out "E:\проект\autocut_out" \
  --no-llm
```

Стадии:

1. `index` — построить или загрузить индекс.
2. `direct` — получить 1–3 плана.
3. `edit` — выбрать и оптимизировать.
4. `critic` — проверить и при необходимости починить.
5. `export` — XML, EDL, отчёт.
6. `preview` — 360p MP4 (необязательно).
7. `import` — только через панель, не из CLI.

Флаги MVP:

- `--no-llm` — детерминированный режиссёр;
- `--dry-run` — только индекс и план, без XML;
- `--resume` — продолжить с последней стадии;
- `--profile` — профиль стиля;
- `--keep-work` — не чистить `_work`.

### 4.2. `ml/index.py`

Обязанности:

- обойти папку и найти видео, музыку, REC-файлы;
- посчитать `sha1`, `mtime`, `size`, `ffprobe`-метаданные;
- нарезать источники на сегменты;
- распознать речь и привязать слова к сегментам;
- оценить резкость, тряску, чёрные кадры, экспозицию;
- определить крупность и людей, где это возможно;
- описать нарезку через Qwen2-VL;
- посчитать эмбеддинги подписей;
- сохранить индекс и кеш по каждому источнику.

Кеш:

```
<out>/_work/index/<sha1>.json
<out>/_work/index/manifest.json
```

Ключ кеша: `sha1 + mtime + size + модель + версия схемы`. Если модель
или настройки изменились, пересчитывается только нужная часть.

Сегментация MVP:

1. границы сцен через ffmpeg `scdet` (порог из настроек);
2. если сцен слишком много — склеиваем до 1.5–3 с;
3. дополнительно режем по границам фраз из транскрипта;
4. для интервью используем готовые куски `interview.py`.

### 4.3. `ml/director.py`

Вход — не весь транскрипт, а сжатая карта:

```json
{
  "genre": "digest",
  "target_sec": 120,
  "brief": "Показать мероприятие, объяснить тему, дать голоса участникам",
  "beats": ["hook", "context", "event", "voices", "close"],
  "sources": [
    {"id": "C0101", "role": "standup", "topics": ["наука"], "duration": 45},
    {"id": "C0098", "role": "interview", "topics": ["AI"], "duration": 180}
  ]
}
```

Выход — только JSON, без XML и без свободного текста:

```json
{
  "version": 1,
  "genre": "digest",
  "target_sec": 120,
  "story": {
    "title": "Выходи решать",
    "beats": [
      {"id": "hook", "goal": "зацепить", "start_sec": 0, "end_sec": 12},
      {"id": "context", "goal": "объяснить", "start_sec": 12, "end_sec": 30}
    ]
  },
  "candidates": [
    {"beat": "hook", "source": "C0101", "in": 0.0, "out": 3.2, "role": "standup", "reason": "..."}
  ]
}
```

Правила:

- модель не видит путей и не может вызвать инструменты;
- транскрипт передаётся как данные в жёстких разделителях;
- ответ проверяется схемой и смысловыми правилами;
- при ошибке — повтор с указанием конкретной ошибки, не больше двух раз;
- три кандидата при `temperature=0.7`, выбор — по оценке Editor;
- без модели работает детерминированный режиссёр: биты по правилам,
  кандидаты по темам и качеству.

Модель MVP: `Qwen2.5-7B-Instruct`, 4-bit, context 8k. Для 6 ГБ —
только 7B, последовательно с остальными моделями. 14B — опция для
12–24 ГБ.

### 4.4. `ml/editor.py`

Модель кандидата:

```python
@dataclass
class Candidate:
    source_id: str
    src_in: float
    src_out: float
    role: str          # standup | interview | broll
    beat: str
    shot_size: str
    people: list[str]
    quality: float
    topic_score: float
    text: str
```

Жёсткие ограничения:

- хронометраж в пределах ±5% от цели;
- один и тот же источник не идёт подряд;
- соседние номера файлов не идут подряд;
- не больше двух кусков подряд одной крупности;
- не больше двух кусков подряд с одним человеком;
- нет повтора темы;
- длина куска: стендап 2–5 с, нарезка 1.2–2.6 с, интервью 2–6 с;
- V1 — только голос, V2 — только нарезка;
- A2 — только рекордер, A3 — только музыка.

Целевая функция:

```
score =
    0.35 * story_match
  + 0.20 * quality
  + 0.15 * variety
  + 0.15 * continuity
  + 0.10 * rhythm
  + 0.05 * topic_coverage
  - penalties
```

Алгоритм MVP:

1. для каждого бита — топ-20 кандидатов;
2. beam search по битам с проверкой ограничений;
3. локальные улучшения: замена, сдвиг границы, обмен местами;
4. финальная подгонка длительности;
5. выравнивание по музыке, если есть beat grid.

Позже — OR-Tools/ILP. Но и beam search на 5–7 битах даёт управляемый
результат без тяжёлой зависимости.

### 4.5. `ml/critic.py`

Технические проверки:

- `premiere.check_xml()` и `missing_media()`;
- у каждого `clipitem` есть `<file>`;
- превью открывается, fps/разрешение/длительность совпадают;
- нет чёрных и замороженных кадров;
- громкость: цель −20 LUFS, истинный пик −6 dBTP;
- синхронизация рекордера: первый и последний слог в пределах 0.25 с;
- нет оборванных фраз и повторов.

Смысловые проверки:

- все биты покрыты;
- нет двух одинаковых подписей;
- нет двух подряд кадров одной крупности/человека;
- спикеры представлены;
- тема не потеряна;
- хук в первых 5 секундах.

Формат `critique.json`:

```json
{
  "version": 1,
  "score": 0.82,
  "issues": [
    {"level": "error", "code": "audio_sync", "clip": "a2-003",
     "message": "рекордер опаздывает на 0.4 с", "fix": "shift"},
    {"level": "warn", "code": "same_size", "clip": "v2-007",
     "message": "три средних плана подряд", "fix": "replace"}
  ],
  "accepted": false
}
```

Починка — только разрешённые операции: `trim`, `extend`, `replace`,
`swap`, `drop`, `shift_audio`. Critic не имеет права менять смысл
битов. Максимум два прохода; если не сошлось — отдаём черновик с
предупреждениями.

### 4.6. `ml/style.py`

Из готового `.prproj` через `io/prproj.py` извлекаем:

- длительности кусков по ролям;
- доли стендапа, нарезки, интервью;
- последовательность крупностей;
- смены говорящего;
- места музыки, титров и маркеров;
- среднюю длину плана до/после кульминации.

Результат — `style_profile.json`. Им пользуются Director (бюджеты
битов) и Editor (штрафы за ритм). После правок монтажёра сравниваем
автоплан с финалом:

- какие куски оставлены;
- какие выброшены;
- где сдвинуты границы;
- какие куски добавлены.

Это пары предпочтений. В MVP — обновление весов и простой ranker
(LightGBM/логистическая регрессия). Дообучение LLM не делаем.

## 6. Индекс: как считаем

### 6.1. Порядок

1. `ffprobe` — длительность, fps, размер, звук.
2. `sha1` — ключ кеша.
3. Сцены — ffmpeg `scdet`.
4. Речь — `speech.words_of`.
5. Качество — `sharpness`, `blackframes`.
6. Люди/крупность — `detect.analyse_video`.
7. Описание — `describe` только для нарезки.
8. Темы — `theme.label_pool` / `embed_labels`.

### 6.2. Что важно не сломать

- **Нельзя считать `sha1` каждого файла на каждом запуске.** Для
  больших карт это минуты. Кеш по `path + size + mtime`; `sha1` — при
  первом появлении и при смене размера.
- **Модели не живут одновременно.** После ASR — `speech.release()`,
  после VLM — `describe` освобождает модель, после эмбеддингов —
  `theme.release_embedder()`.
- **Ошибка одного файла не роняет индекс.** Пишем `error` в источник и
  идём дальше.
- **Прогресс.** Каждый шаг пишет `index: 12/126` в журнал задачи.

## 7. Director: как получается история

### 7.1. Биты

Для дайджеста:

1. `hook` — 0–12 с, самый сильный кадр;
2. `context` — 12–30 с, стендап объясняет;
3. `event` — 30–70 с, нарезка;
4. `voices` — 70–105 с, интервью;
5. `close` — 105–120 с, финал.

Это стартовый шаблон, не догма. Director может сдвигать границы, но не
может выбросить `hook` и `close` в MVP.

### 7.2. Промпт

Системная часть:

- ты продюсер короткого ролика;
- у тебя есть только факты из индекса;
- нельзя выдумывать события и цитаты;
- верни строго JSON по схеме;
- если фактов не хватает — верни `"needs_more": [...]`.

Пользовательская часть:

- бриф;
- жанр;
- цель;
- список битов;
- по 10–20 сегментов на роль с темами и качеством;
- профиль стиля;
- ограничения.

Транскрипт не вставляем целиком: только текстовые подписи сегментов.
Это экономит контекст и снижает риск, что модель начнёт «писать сценарий
по словам».

### 7.3. Валидация

- JSON Schema;
- сумма битов ≈ цели;
- каждый бит имеет хотя бы одного кандидата;
- нет ссылок на несуществующие `source`;
- нет кандидатов короче минимума;
- `reason` не пустой.

### 7.4. Без LLM

Детерминированный режиссёр:

- стендап — лучший непрерывный заход речи;
- нарезка — по темам и качеству;
- интервью — по одному сильному ответу на спикера;
- биты — по долям из `style_profile`.

Это важно: MVP должен работать на машине без LLM и без GPU.

## 8. Editor: как получается таймлайн

### 8.1. Кандидаты

Для каждого сегмента считаем:

- `story_match` — совпадение темы с битом;
- `quality` — резкость/тряска/чёрные кадры;
- `speech` — есть ли речь и насколько она разборчива;
- `visual` — описание и эмбеддинг;
- `novelty` — не повторяет ли уже выбранное;
- `continuity` — не ломает ли ось/направление.

### 8.2. Поиск

MVP:

- beam width 8;
- состояние — выбранные куски, суммарная длина, последние 2 куска;
- переход — добавить кандидата, если проходят ограничения;
- оценка — целевая функция;
- финальная подгонка — trim/extend в пределах 10%.

Позже:

- ILP для глобального оптимума;
- динамическое программирование по битам;
- музыкальный beat grid.

### 8.3. Музыка

Если музыка есть:

- BPM и beat grid через `librosa` (или ffmpeg `astats` + onset, если
  не хотим зависимость);
- склейки в пределах ±0.15 с от сильной доли;
- смена крупности — на фразе;
- ducking: музыка −6 дБ в дайджесте, −12 дБ под голосом;
- fade 0.3–0.5 с на входе/выходе.

Если музыки нет — ритм по паузам речи.

## 9. Critic: как не отдать брак

### 9.1. Технический контур

- `check_xml`;
- `missing_media`;
- ffprobe превью;
- black/freeze;
- loudness;
- sync;
- длительность.

### 9.2. Смысловой контур

- покрытие битов;
- повторяемость;
- разнообразие крупностей;
- баланс спикеров;
- целостность фраз;
- хук.

### 9.3. Починка

| Проблема | Разрешённое действие |
|---|---|
| кусок длиннее | trim |
| кусок короче | extend |
| плохой кадр | replace |
| три средних плана | swap |
| нет темы | drop + replace |
| звук опаздывает | shift_audio |
| перебор хронометража | trim/remove |

После починки — повторный прогон технических проверок. Смысловые
проверки повторяются только для изменённых битов.

## 10. Обучение на референсе

### 10.1. Что извлекаем

`io/prproj.py` уже даёт клипы, дорожки, `in/out`, позиции. Добавляем
агрегаторы:

- `role` — по папке/имени/дорожке;
- `cut_length` — распределение по ролям;
- `shares` — экранное время;
- `shot_size_sequence` — по описаниям/детектору;
- `speaker_sequence` — по лицам/голосу;
- `music_segments` — по A3;
- `title_segments` — по маркерам/графике;
- `transition_points` — по стыкам.

### 10.2. Сравнение

Для каждого автокуска ищем лучший человеческий кусок по:

- тому же источнику;
- пересечению `in/out`;
- той же роли.

Метрики:

- `retention` — доля автокусков, оставшихся у монтажёра;
- `cut_distance` — медиана сдвига границ;
- `selection_overlap` — доля пересечения выбранных источников;
- `duration_error`;
- `technical_pass`.

### 10.3. Обновление

MVP:

- обновляем веса целевой функции по `retention` и `cut_distance`;
- храним пары «авто-кусок → человеческий кусок»;
- при накоплении 50+ пар — LightGBM ranker.

Не делаем:

- fine-tune LLM на одном проекте;
- обучение с нуля;
- «стиль» без явного согласия монтажёра.

## 11. Premiere: как отдаём результат

### 11.1. Секвенция

```
V1  голос: стендап + интервью
V2  нарезка
A1  звук камеры (link с V1)
A2  рекордер (один трек)
A3  музыка
```

### 11.2. Импорт

- `app.project.importXML(File(xmlPath))`;
- дождаться появления sequence;
- переименовать в `AutoCut / <жанр> / <дата>`;
- открыть;
- показать отчёт.

`importFiles` не использовать: он не гарантирует разбор FCP7.

### 11.3. Титры

MVP:

- маркеры с именем/должностью;
- PNG-плашки рядом с XML;
- отчёт `plashki.txt`.

Позже:

- MOGRT через ExtendScript;
- Local Templates;
- автоматическая подстановка имени.

### 11.4. Превью

- 360p, 25 fps, H.264;
- звук — микс A1/A2/A3;
- длительность — как у плана;
- используется для critic и для быстрого просмотра.

## 12. Модели и видеопамять

| Модель | Задача | Примерно VRAM | Когда |
|---|---|---|---|
| faster-whisper large-v3 | речь | ~3 ГБ | индекс |
| Qwen2-VL-2B | описание кадров | ~4.4 ГБ | индекс нарезки |
| e5-large | эмбеддинги | ~2.2 ГБ | темы |
| Qwen2.5-7B 4-bit | режиссёр | ~4.5–5 ГБ | план |
| YOLOv8n-pose | лица/крупность | ~0.5 ГБ | индекс |

Правила:

- одновременно — одна тяжёлая модель;
- `ml/model_manager.py` (новый) или `core/gpu.py` + общий `Lock`;
- после каждой стадии — `release()`;
- при нехватке VRAM — CPU fallback для e5 и Qwen2-VL;
- 6 ГБ — это 7B, не 14B;
- LLM не грузится, если `--no-llm`.

## 14. Тесты и критерии качества

### 14.1. Без моделей

- схема `edit_plan` — валидный/невалидный JSON;
- конвертация плана в строки `premiere.py`;
- ограничения Editor на синтетических кандидатах;
- извлечение профиля из тестового `.prproj`;
- `check_xml` на golden-файле.

### 14.2. Синтетические фикстуры

1. Дайджест: стендап + 10 нарезок + 2 интервью + музыка.
2. Интервью: две камеры, два микрофона, рекордер.
3. Вертикаль: 16:9 → 9:16.

Фикстуры — короткие цветные клипы с известными таймкодами и текстом.
Они позволяют проверить план и XML без GPU.

### 14.3. Живой Premiere

Чек-лист:

- XML импортируется без пустой панели;
- секвенция 1920×1080, 25 fps;
- V1/V2/A1/A2/A3 на месте;
- A2 — один трек, звук синхронен;
- маркеры видны;
- длительность совпадает.

### 14.4. Метрики MVP

- технический проход — 100%;
- хронометраж — ±5%;
- нет P0-багов;
- `retention` ≥ 60% на 3 проектах;
- медиана `cut_distance` ≤ 1.0 с;
- оценка монтажёра ≥ 3.5/5;
- повторный прогон быстрее первого в 2 раза.

## 17. Definition of Done

MVP считается готовым, когда:

1. Монтажёр устанавливает панель и запускает движок одной командой.
2. Выбирает папку и жмёт «Собрать».
3. Через 25 минут на 30 минут материала получает секвенцию.
4. Секвенция импортируется в Premiere 2026 без ошибок.
5. V1/V2/A1/A2/A3 разложены правильно.
6. A2 — один трек, звук синхронен.
7. Хронометраж в пределах ±5%.
8. Critic не пропускает чёрные кадры, рассинхрон и оборванные фразы.
9. Есть отчёт: что выбрано, почему, что не вошло.
10. Тесты `python run_tests.py` проходят.
11. На трёх реальных проектах `retention` ≥ 60%.
12. Монтажёр говорит: «это можно править», а не «это надо пересобирать».

## 20. Итог

AutoCut уже умеет 70–80% технической работы. Не хватает двух слоёв:
Director (история) и Critic (самопроверка). Если добавить их поверх
существующего индекса и XML, получится не «нейросеть, которая всё
понимает», а локальный агент монтажа: он строит черновик, объясняет
решения и оставляет монтажёру правку, а не рутину.
