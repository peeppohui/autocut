# AutoCut — заметки для разработчиков

Неочевидное, что стоило выяснить экспериментально. README не переписывает —
здесь то, что иначе пришлось бы добывать заново.

Если хотите что-то добавить — начните с раздела **«Проверка»**: половина

## С чего начать

```bash
cd plugin
python run_tests.py        # все тесты, ~1 минута
python -m src.modes.interview --help
```

Модули запускаются как `python -m src.<папка>.<модуль>`. Импорты между
папками работают через `src/bootstrap.py`: он добавляет `core`, `modes`,
`ml`, `io`, `config` в `sys.path`, после чего обычный `import sync` или
`from srt import build_srt` работают без изменений.

## Грабли Premiere Pro 26 и FCP7 XML

### Главное правило: у каждого `clipitem` обязан быть `<file>`

Premiere **молча**, с пустым сообщением в окне «File Import Failure»,
отказывается импортировать весь XML, если хотя бы один клип видеодорожки
не ссылается на файл. Никакого указания, какой именно клип сломан.

Это случилось в режиме `--stacked`: ветка создавала клип второго ракурса
на V2, но не прописывала `<file>` основному клипу на V1. Все 90 клипов
верхней дорожки остались без ссылки на медиа — и не импортировалось ничего.

Регрессия закрыта тестом «у каждого клипа есть `<file>`» в
`tests/test_multicam.py`. Не отключать.

### Как проверить, что новый экспорт вообще грузится

Не гадать. Собрать лестницу файлов и попросить импортировать по порядку:

1. `1_plain.xml` — одна видеодорожка, без второго ракурса
2. `2_stacked_min.xml` — две дорожки, клипы второго ракурса без `<labels>`/`<logginginfo>`
3. `3_stacked_full.xml` — полный вариант

Первый не грузившийся файл и указывает на виновника. Так вышло и здесь:
`1` открылся, `2` и `3` нет — значит дело в самой второй дорожке, а не в
оформлении на ней. Разница `1` и `2` показала ноль `<file>` на V1.

### Ограничения, обойти которые не вышло

- **FCPXML Premiere не импортирует вообще.** Конвертировать нечем.
  Формат — FCP7 (xmeml v5).
- **`<multiclip>` Premiere 26 не читает.** Файл с углами не импортируется
  ни с `<file>` на клипе, ни с полными `in`/`out` у углов — проверено
  четырьмя вариантами структуры на починенной сборке.
- Рабочих пути два: **две видеодорожки** с переключением глазком, либо
  **общий таймкод в файлах** плюс ручное создание мультикама в самом
  Premiere. Ветка `--multiclip` из `premiere.py` выброшена как мёртвая.
- **UXP-панели недоступны** без Creative Cloud, а в Premiere 26 убран
  `File → Scripts`. Кода панели в проекте нет.
- Пустая дорожка (0 `clipitem`) в `<media>` — не причина отказа, проверено,
  но `totalExplodedTrackCount` на ней лучше не оставлять.

### Сверка с DTD

`FCPXMLv5.dtd` с сайта Apple полезна, но с оговорками:

- модели элементов записаны как `(a | b | c)*` — **порядок элементов не важен**;
- выкачивание теряет `ATTLIST`, поэтому валидатор ругается на атрибуты
  `name`, `currentExplodedTrackIndex`, `totalExplodedTrackCount` — это ложь;
- рабочий файл даёт те же 4 «ошибки». Ориентир — не «0 ошибок», а
  «столько же, сколько у заведомо рабочего»;
- у нас есть лишнее вложение `<sourcetrack><sourcetrack>` — Premiere его ест.

## Проверка

Тесты — простые скрипты, pytest в проекте нет. Гонять через runner:

```powershell
cd plugin
python run_tests.py
```

Признак успеха — **код возврата 0 и метка в конце вывода**.

Кому это важно: проверка «есть ли слово `OK` в выводе» — ложь. Упавший
тест успевает напечатать несколько `OK` перед падением, и такой прогон
выглядит зелёным. Так три теста падали незамеченными, пока runner не
начал смотреть на код возврата.

**Тесты не должны открывать модальные окна.** `messagebox.showwarning`
в тесте вешает прогон навсегда — подменяйте заглушкой.

## Сборка вручную

```powershell
cd plugin
$d = "<папка проекта>"
python -m src.io.premiere --timeline "$d\rz\selects.csv" --out "$d\ryba.xml" --edl "$d\ryba.edl" --stacked
```

`--edl ""` не принимается: пустую строку argparse проглатывает, указывай
путь.

Настоящий мультикам готовится так — таймкод впечатывается без
перекодирования, дальше три клика в Premiere:

```powershell
python -m src.ml.multicam --input "$d\synced\ref.mp4" "$d\synced\cam.mp4" --outdir "$d\multicam"
```

## Стиль

- Комментарии и тексты для пользователя — по-русски.
- Комментарий объясняет **почему**, а не пересказывает код.
- Оформление окна берётся из `ui/theme.py`. Не создавайте элементы через
  голый `ctk` — окно рассыплется на две разные программы.

## Переводы строк

В репозитории везде **LF**, `core.autocrlf=false`. Если переписать файл
скриптом на Python, он молча станет CRLF, и git покажет весь файл как
изменённый — тысячи строк шума вместо правки.

Переписывайте файлы через инструменты редактирования. Если пришлось
скриптом — верните LF:

```powershell
$p = "plugin\src\modes\interview.py"
$b = [IO.File]::ReadAllBytes($p)
$out = New-Object System.Collections.Generic.List[byte]
for ($i = 0; $i -lt $b.Length; $i++) {
  if ($b[$i] -eq 13 -and $i -lt $b.Length - 1 -and $b[$i + 1] -eq 10) { continue }
  $out.Add($b[$i])
}
[IO.File]::WriteAllBytes($p, $out.ToArray())
```

## Мелочи, которые стоят времени

- **OpenCV на Windows не понимает кириллицу в путях.** `cv2.imread` вернёт
  `None`, `cv2.imwrite` молча ничего не запишет. Читайте через
  `np.frombuffer(path.read_bytes())` + `cv2.imdecode`, пишите через
  `cv2.imencode` + `path.write_bytes()`.
- **`np.clip` в `int16` переполняется молча.** `247 * 255 = 62985` не
  влезает в диапазон, numpy заворачивает в `−2551`, и результат получается
  обратным. Считайте в `float32`.
- **Tk масштабирует картинки только целым числом** (`subsample`). Если
  просишь ширину 160, а файл 200 — получишь 100. Делайте файлы ровно вдвое
  больше отображаемого.
- **Не называйте атрибут `self.state`** — затирает метод Tk с тем же
  именем. На ttk это было незаметно, на customtkinter окно падало с
  `TypeError: 'dict' object is not callable`.
