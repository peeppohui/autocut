# AutoCut — заметки разработчика (v2)

Версия `v1` заморожена тегом `v1`. Ветка `v2` — переделка: панель
Premiere как единственный интерфейс, тонкий локальный движок, без Tk-окна
и без зоопарка режимов. Старые подробности при необходимости смотрите в
теге `v1`; здесь только то, что важно для v2.

## С чего начать

```powershell
cd plugin
E:\AutoCut\.tools\python311\python.exe run_tests.py
```

Портативные Python 3.11.9, Node 24, ffmpeg/ffprobe 9 лежат в
`E:\AutoCut\.tools`. В PATH их может не быть — это нормально.
`AutoCut.bat` поднимает движок вручную, панель обычно делает это сама.

Признак успеха тестов — **код возврата 0 и маркер в конце вывода**.
Проверка «есть ли слово OK» — ложь: упавший тест успевает напечатать
несколько `OK` перед падением.

## Границы v2

- `premiere_panel/` — единственный UI. Логики монтажа там нет.
- `engine/` — новый движок: `api`, `index`, `director`, `editor`,
  `packs`, `export`, `doctor`.
- `src/` — проверенное ядро v1, которое постепенно переезжает в `engine`.
- `src/mcp_server/` — только обёртки старых импортов. Канонический
  транспорт — `engine/api.py`, очередь задач — `engine/jobs.py`.
- Один жанр = один пак настроек, а не копия пайплайна.

Не возвращать без причины: Tk-окно, отдельные режимы-клоны, MCP как
самостоятельный продукт, «универсальный монтаж любого видео одной кнопкой».

## Premiere Pro 26 и FCP7 XML

### У каждого `clipitem` обязан быть `<file>`

Premiere **молча** отказывается импортировать весь XML, если хотя бы один
клип видеодорожки не ссылается на файл. Сообщение пустое, виновника не
показывает. Это уже стоило потерянного импорта в режиме `--stacked`.

Регрессия: тест «у каждого клипа есть `<file>`» в `test_multicam.py`.

### Как проверять новый экспорт

Собирать лестницу и импортировать по порядку:

1. `1_plain.xml` — одна видеодорожка;
2. `2_stacked_min.xml` — две дорожки, второй ракурс без оформления;
3. `3_stacked_full.xml` — полный вариант.

Первый не открывшийся файл и указывает на виновника. Так уже нашли
отсутствие `<file>` на V1.

### Ограничения, которые не обошли

- **FCPXML Premiere не импортирует вообще.** Только FCP7 (xmeml v5).
- **`<multiclip>` Premiere 26 не читает.** Проверено четырьмя вариантами.
  Рабочий путь — две видеодорожки с переключением глазком.
- **UXP-панели требуют Creative Cloud**, поэтому используется CEP.
- **Пустая дорожка** (0 `clipitem`) не ломает импорт, но
  `totalExplodedTrackCount` на ней лучше не оставлять.

### Клип без колонки `audio` занимает свою звуковую дорожку

Это не баг. Перебивка без микрофона получает собственную дорожку и звучит.
Решение зафиксировано тестом «перебивка получила свою звуковую дорожку».
Не отключать линковку ради «лишней» дорожки.

Самостоятельные дорожки объявляются после связанных, поэтому номера из
`settings.json` — пожелание, а не адрес в готовой секвенции.

## Рекордер: оригинал, а не нарезанный WAV

План хранит **оригинальный файл рекордера** и его собственные
`audio_in` / `audio_out` / `audio_duration` / `audio_track=A2`.

Почему нельзя класть заранее нарезанный WAV: он начинается с нуля, а
`premiere.py` для аудиоклипа берёт `in/out` из видео. Premiere ищет
не там и играет не то. Нарезанный WAV допустим только если экспортёр
явно ставит ему `in=0`.

Все куски рекордера должны попадать на **одну** дорожку `A2`. Для этого
в CSV есть `audio_track`, а `premiere.py` строит имя `X:A2`, а не
`M:<имя файла>` на каждый кусок.

`digest.main` делает `base = Path(args.input).resolve()`, иначе путь
рекордера, найденный относительно относительного `base`, приклеится
второй раз в `write_plan`.

## Звук: две дорожки и никакого loudnorm

| куда | частота | зачем |
|---|---|---|
| `_guest.wav` / `_host.wav` | 16 кГц моно | вход Whisper |
| `_guest_full.wav` / `_host_full.wav` | 48 кГц, как в исходнике | дорожка Premiere |

Одной дорожкой нельзя: либо распознавание втрое медленнее, либо Premiere
получает телефонный звук.

Нормализация — усиление + `alimiter`, **не** `loudnorm`. `loudnorm`
сжимает динамику с 20 до 14 LU и работает в 10 раз дольше. Цель —
`target_lufs = -20`, потолок `true_peak_db = -6`: это разные шкалы,
путать нельзя. `alimiter` держит пик отсчётов, а не истинный; при
промахе опускать надо предел, а не усиление.

Перезаписывать вход ffmpeg нельзя: писать во временный файл и
подменять исходник после успеха.

## Модели: измерено, а не на глаз

- **Whisper:** доля слов с уверенностью ниже 0.5 — large-v3 3%,
  medium 6%, small 9%, base 15%. `base` путает слова. По умолчанию
  `large-v3`, на слабой видеокарте — `medium`.
- **Qwen2-VL-2B** описывает кадры по-русски. 360×360, один кадр,
  fp16 — около 3.3 с на клип. Два кадра и полный размер дают 22 с.
- **e5-large** — смысловые эмбеддинги. Перед ней Whisper надо
  освободить: 6 ГБ не держат обе модели.
- **YOLOv8-pose** уже есть в проекте; отдельный детектор лиц не нужен.

Модели грузить по очереди, а не одновременно. Это правило для `engine/`.

## Дайджест: рецепт с готового ролика

Готовый дайджест 101.7 с: стендап 21%, нарезка 55%, интервью 24%.
Первые числа 22/25/53 были ошибкой: их считали по звуку, а нарезка несёт
голос мероприятия.

- Стендап — **один связный заход речи**, а не куски по две секунды.
  Семь кусков в эталоне — смена ракурса при непрерывном звуке.
- Нарезка — вырезки **1.2–2.6 с** (меры 1.2, 1.55, 1.9, 2.25, 2.6),
  а не клип целиком.
- Интервью — по границам фраз, 1–8 с.
- Нарезка работает и поверх речи, и в паузах.
- Порядок — по теме, а не по номерам файлов.
- Не повторять одну тему и не ставить подряд соседние номера.
- Не больше двух подряд одной пары (крупность, кто в кадре).
- Плашки на говорящих — работа монтажёра; в исходниках их нет.
- 120 с — потолок, а не цель.

Смысл кадра берётся из **его собственного звука** (что говорили в
микрофон камеры) плюс описание Qwen. CLIP для этого не подходит: между
любыми кадрами одного мероприятия сходство 0.58–0.74.

## Синхронизация

`global_max_lag_sec` — широкое окно попарного измерения (300 с).
`max_lag_sec` — узкое окно запасного поиска по одной дорожке (60 с):
на широком окне появляются ложные пики. Это разные роли, не опечатка.

Три грабли `find_offset`: `argmin` от пустого массива; выбор ближайшего
к нулю кандидата вместо сильнейшего; пик на самом краю окна.

## Стиль

- Комментарии и тексты для пользователя — по-русски.
- Комментарий объясняет **почему**, а не пересказывает код.
- Не создавать второй UI и второй пайплайн «на всякий случай».
- В репозитории **LF**, `core.autocrlf=false`. Скрипт на Python молча
  сделает CRLF и покажет весь файл изменённым.
- OpenCV на Windows не понимает кириллицу в путях: читать через
  `np.frombuffer` + `cv2.imdecode`, писать через `cv2.imencode`.
- `np.clip` в `int16` переполняется молча: считать в `float32`.
